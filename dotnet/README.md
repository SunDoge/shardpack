# SunDoge.ShardPack

.NET 8+ bindings for the Rust ShardPack sequential container reader and writer.
The NuGet package and namespace are `SunDoge.ShardPack`. Native declarations are
generated by [csbindgen](https://github.com/Cysharp/csbindgen); Rust remains the
format implementation, including CRC32C, BLAKE3, Zstd and AES-256-GCM.

```csharp
using SunDoge.ShardPack;

byte[] id = Convert.FromHexString("00112233445566778899aabbccddeeff");
using (var output = File.Create("example.spk"))
using (var writer = new ShardWriter(output,
    new WriterOptions { Codec = BlockCodec.Zstd }))
{
    writer.Write(id, "hello"u8, flags: 7);
    ShardSummary summary = writer.Finish();
    Console.WriteLine(Convert.ToHexString(summary.ShardId));
}

using var reader = new ShardReader(File.OpenRead("example.spk"));
while (reader.Read() is { } record)
    Console.WriteLine(System.Text.Encoding.UTF8.GetString(record.Payload));
```

Pass a 32-byte `key:` to both constructors for encrypted shards. No key is stored
in the shard. Sample IDs are raw 16-byte sequences: if using `Guid`, explicitly
choose its byte order; the SDK does not implicitly convert GUIDs.

Any readable/writable synchronous `Stream` works, including non-seekable streams.
For HTTP, supply a streaming response body (for example `HttpClient` with
`ResponseHeadersRead`); for S3 use the stream supplied by your S3 SDK. These calls
are synchronous and do not provide async prefetch. The initial .NET SDK exposes
individual shard containers; dataset manifests, cache, scheduling, shuffling and
cloud authentication are not yet wrapped.

Records own their managed `byte[]` payloads and survive subsequent reads. Writes
accept spans and borrow their buffers only until the call returns. Per-instance
operations are serialized. `Dispose()` closes the native handle and, by default,
the stream; use `leaveOpen: true` to retain it. Always call `Finish()` explicitly:
disposing an unfinished writer aborts it and may leave an incomplete shard.
An I/O or native write failure makes that writer unusable. Managed stream failures
are attached to `ShardPackException.InnerException`; exceptions never cross the C ABI.
`ReaderLimits` bounds block allocation; managed record payloads must fit in a .NET
array. Block checksums and AEAD are checked, but a bare stream cannot establish
the expected shard size/hash: compare the completed object to its trusted manifest
when whole-object identity or exact block-boundary truncation detection matters.

## Build and test

Install Rust, a C build toolchain (including CMake for AWS-LC builds), and the
.NET SDK managed by mise (`mise install`), then:

```sh
mise run test:dotnet
dotnet pack dotnet/src/SunDoge.ShardPack -c Release -o dotnet/artifacts
```

Building the C# project invokes Cargo with `--locked`, generates bindings into
`obj/`, and copies the native library. The package version follows the Cargo
workspace. `dotnet pack` currently bundles **only the build machine's native RID**;
it does not build a universal package. Linux x64 is tested in CI. The native
library inherits the host compiler/libc requirements; no manylinux/glibc 2.17
guarantee is made for this NuGet package. NuGet publishing is not automated yet.
